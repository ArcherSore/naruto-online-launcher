# Feature Specification: 腾讯国服扫码登录与游戏启动基础链路

**Feature Branch**: `001-tencent-game-launch`

**Created**: 2026-07-20

**Status**: Draft

**Input**: User description: "将当前应用面向用户的核心流程改造为腾讯国服《火影忍者 OL》专用启动流程，使用户能够通过腾讯官方二维码登录、选择区服，并在启动器内部进入和运行游戏。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 首次扫码并进入游戏 (Priority: P1)

首次使用启动器的用户打开一个全新 Profile 后，看到腾讯官方登录和选服页面。用户通过官方二维码完成登录，选择一个有效区服并进入游戏，随后在启动器内部看到可交互的游戏内容。

**Why this priority**: 这是启动器面向腾讯国服用户的最小可用闭环；没有该链路，用户无法使用产品的核心价值。

**Independent Test**: 使用不含腾讯登录状态的全新 Profile，从启动入口完成扫码、选服和进入游戏；当游戏内容在启动器内部显示并能响应一次正常鼠标操作时，该故事可独立验收。

**Acceptance Scenarios**:

1. **Given** 用户打开一个全新 Profile，**When** 用户启动该 Profile，**Then** 启动器显示腾讯官方选服页面 `https://huoying.qq.com/server/website/` 及其官方扫码登录入口。
2. **Given** 官方二维码可用且用户尚未登录，**When** 用户扫码并在腾讯官方流程中确认登录，**Then** 用户能够在官方页面看到并选择有效区服。
3. **Given** 用户已登录并选择有效区服，**When** 用户点击进入游戏，**Then** 启动器内部进入对应的 `game.huoying.qq.com/main.html` 游戏页面，而不是把游戏交给外部浏览器。
4. **Given** 游戏页面已完成加载，**When** 用户在游戏内容区域执行一次正常鼠标操作，**Then** 游戏内容对该操作作出可观察响应。

---

### User Story 2 - 复用有效登录状态 (Priority: P2)

Electron 主进程保持运行时，用户关闭并重新打开同一 Profile 的游戏窗口，若腾讯官方仍认可该 Profile 的登录状态，用户无需重新扫码即可继续选服和进入游戏；若登录状态已失效，用户安全返回腾讯官方扫码登录流程。

**Why this priority**: 会话复用减少重复登录成本，而失效后的安全回退保证用户无需清理应用数据也能恢复使用。

**Independent Test**: 分别准备登录状态有效和已失效的同一 Profile，保持 Electron 主进程运行、关闭并重新打开该 Profile 的游戏窗口，验证前者无需扫码即可继续选服、后者明确返回官方扫码入口，并确认另一 Profile 的状态不受影响。

**Acceptance Scenarios**:

1. **Given** 同一 Profile 已完成登录、腾讯官方仍认可其会话且 Electron 主进程保持运行，**When** 用户关闭并重新打开该 Profile 的游戏窗口，**Then** 用户无需再次扫码即可继续使用官方选服页面并手动进入游戏。
2. **Given** 同一 Profile 的腾讯登录状态已经失效且 Electron 主进程保持运行，**When** 用户重新打开该 Profile 的游戏窗口或在选服、进入游戏过程中被判定为未登录，**Then** 启动器返回腾讯官方扫码登录流程，并允许用户重新扫码恢复。
3. **Given** Profile A 与 Profile B 均存在，**When** Profile A 登录、退出、会话失效或重新扫码，**Then** Profile B 的登录状态和页面状态不发生改变。

---

### User Story 3 - 从启动失败中可靠恢复 (Priority: P3)

当登录页、选服页、页面跳转或游戏内容加载失败时，用户可以从管理卡片使用常态可见的“刷新”按钮重新加载当前安全页面，而不会被送入不支持游戏的外部浏览器或陷入无限刷新。管理卡片不再展示不可靠的流程状态说明或动态故障动作。

**Why this priority**: 官方网页、网络和游戏内容均可能失败；可诊断且受控的恢复路径是稳定日常使用的必要保障。

**Independent Test**: 分别模拟登录页加载失败、选服页加载失败、进入游戏跳转失败、游戏加载失败和会话中途失效，验证运行中的 Profile 始终显示“刷新”，用户可通过该按钮安全重载当前可信角色，且无需删除应用数据。

**Acceptance Scenarios**:

1. **Given** Profile 尚未认证且官方登录 UI 加载失败，**When** 用户点击该运行中 Profile 的“刷新”，**Then** 启动器重新加载当前已分类的官方页面，且当前 Profile Session 被保留。
2. **Given** Profile 已认证且官方选服页加载失败，**When** 用户点击“刷新”，**Then** 启动器重新加载官方选服页，且当前 Profile Session 被保留。
3. **Given** 从选服页进入游戏的跳转失败，**When** 用户点击“刷新”，**Then** 启动器只重新加载当前已分类的安全角色，不接受 renderer 提交任意 URL。
4. **Given** 游戏内容加载失败或页面无法继续使用，**When** 用户点击“刷新”，**Then** 用户可以重新加载当前游戏页面，且不需要手动删除 Profile 或应用数据。
5. **Given** 任一页面连续失败，**When** 自动恢复未能成功，**Then** 启动器停止自动刷新；管理卡片仍常态保留可由用户逐次触发的“刷新”。

### Edge Cases

- 二维码过期、扫码被取消、腾讯要求额外验证或拒绝登录时，页面保持在官方认证流程，并允许用户按官方页面提示继续或重新获取二维码。
- 会话在选服页停留期间、点击进入游戏后或游戏加载过程中失效时，流程返回官方扫码登录入口，不把失效状态误判为游戏加载错误。
- 完整退出 Electron 主进程并重新启动应用后，腾讯官方可能要求重新扫码；该行为不计为本 Feature 的会话复用失败，也不得通过复制、延长或重放 session Cookie/票据来规避。
- 用户选择的区服无效、维护中、排队中或暂不可进入时，启动器保留官方页面给出的状态，不伪造成功，也不绕过官方限制。
- 官方页面尝试通过新窗口或跳转打开游戏时，游戏仍在启动器内部的受支持窗口中继续；不得因该行为落入外部浏览器。
- 认证子窗自身发生 navigate、redirect、`new-window` 或二次 popup 时，继续执行与父流程相同的精确 URL 分类；未知目标被阻止并保持可恢复状态，不得形成绕过顶层导航契约的窗口链。
- 非核心帮助、协议、客服链接及其他不属于认证、选服、游戏主链的顶层目标默认阻止；本 Feature 不把它们交给系统浏览器。
- 网络断开、域名解析失败、安全连接失败或官方页面长时间无响应时，用户能区分失败阶段并获得受控恢复入口。
- 游戏页地址已进入预期范围但游戏内容为空白、崩溃或无法交互时，不把地址跳转成功等同于游戏启动成功。
- 官方页面结构或跳转方式变化时，流程以明确失败结束，不执行无限重试，也不降级到 Oasis 或其他国际服页面。
- 两个 Profile 同时使用时，一个 Profile 的登录、退出、恢复或数据清理不会改变另一个 Profile 的状态。

## Scope

### In Scope

- 腾讯国服官方扫码登录、选服和进入游戏的用户可见基础链路。
- Electron 主进程保持运行时，同一 Profile 关闭并重开游戏窗口后的有效会话复用、失效识别与重新扫码恢复。
- 不同 Profile 之间的登录状态隔离。
- 登录、选服、页面跳转与游戏加载失败时的有界后台恢复，以及管理卡片常态可见的安全刷新操作。
- 在启动器内部显示并交互国服游戏内容。
- 从用户界面和正常流程中移除 Oasis 登录、地区、服务器及账号密码能力。

### Out of Scope

- 自动扫码、代替用户确认登录、绕过验证码或腾讯风控。
- 自动选择区服、自动进入游戏或任何游戏内自动化行为。
- Oasis、巴西服或其他国际服兼容。
- 多 Profile 的批量启动、调度或自动化编排；本功能只提供后续能力所需的稳定会话与窗口基础。
- 帮助、协议、客服等非核心外链的系统浏览器 allowlist 或 `shell.openExternal` 路由。
- 改变腾讯官方提供的区服可用性、排队、维护或账号安全策略。
- 完整退出 Electron 主进程并重新启动应用后的免扫码会话恢复，以及为实现该能力而复制、延长、重放或自行持久化腾讯 session Cookie/票据。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 启动器面向用户的默认游戏入口 MUST 是腾讯国服官方登录和选服流程。
- **FR-002**: 全新 Profile 启动时 MUST 打开腾讯官方选服页面 `https://huoying.qq.com/server/website/`，并允许用户使用该页面提供的官方二维码登录。
- **FR-003**: 用户认证 MUST 完全由腾讯官方页面完成；启动器 MUST NOT 提供 QQ 账号密码输入或替代官方确认的认证流程。
- **FR-004**: 用户完成官方登录后 MUST 能够浏览并选择腾讯官方页面认定为有效的区服。
- **FR-005**: 用户选择有效区服并点击进入游戏后，启动器 MUST 进入与该选择对应的 `game.huoying.qq.com/main.html` 游戏页面。
- **FR-006**: 游戏页面及其内容 MUST 保持在启动器内部具备游戏运行能力的窗口中，不得转交给外部浏览器承载。
- **FR-007**: 游戏启动成功 MUST 同时满足游戏内容可见和至少一次正常鼠标交互能够获得可观察响应；仅完成地址跳转不得视为成功。
- **FR-008**: 每个 Profile 的腾讯登录状态 MUST 与该 Profile 绑定；Electron 主进程保持运行时，在腾讯官方仍认可会话的前提下，同一 Profile 关闭并重开游戏窗口 MUST 复用同一隔离 Session。
- **FR-009**: 不同 Profile 的登录状态、页面状态和恢复操作 MUST 相互隔离，不得读取、覆盖、清理或污染其他 Profile 的状态。
- **FR-010**: Electron 主进程保持运行时，同一 Profile 关闭并重开游戏窗口且有效会话被复用时，用户 MUST 无需重新扫码即可继续使用官方选服流程；系统 MUST NOT 因会话有效而自动选择区服或自动进入游戏。完整退出 Electron 主进程后的免扫码恢复不属于本 Feature 的验收要求。
- **FR-011**: 会话失效时，启动器 MUST 安全返回腾讯官方扫码登录流程，并允许用户重新扫码恢复，无需手动删除 Profile 或应用数据。
- **FR-012**: 启动器面向用户的界面和正常启动流程 MUST NOT 展示 Oasis 登录、国际服地区、国际服服务器或账号密码功能。
- **FR-013**: 启动器 MUST NOT 采集或存储 QQ 密码，也 MUST NOT 解密、复制、延长、伪造、重放或绕过腾讯登录票据、验证码及风控；MUST NOT 构造未经本 Spec 明确授权的腾讯认证 API 请求。用户针对具体故障作出明确授权时，开发诊断会话 MAY 只读、临时检查解决该故障所必需的官方页面 DOM/HTML、frame、表单、完整 URL、Cookie/Storage、身份或 Session 参数，但 MUST 限定当前本地会话与指定 Profile，MUST NOT 读取 QQ 密码字段、修改认证状态、跨 Profile 访问或把读取值用于登录恢复。
- **FR-014**: 生产网络检查器、普通日志、错误消息、IPC 广播和用户可导出的诊断路径 MUST 通过失败测试与收敛实现，证明不得持久采集、保存、广播或写入完整 URL、query、fragment、Cookie、Set-Cookie、Authorization、JWT、ticket、QQ 身份字段、请求体、响应体和页面源码；常规网络观察只能使用 resource type、origin、pathname、status code、error code，且未知字段 MUST 默认拒绝。FR-013 明确授权的临时本地诊断不受“只能使用安全网络元数据”限制，但原始值 MUST NOT 写入仓库文件、普通日志、错误消息、截图、文件名、IPC、诊断包或长期存储，完成定位后 MUST 立即停止读取并丢弃临时数据。
- **FR-015**: 管理卡片 MUST NOT 显示流程阶段、状态说明或依赖失败识别的动态恢复动作；未启动 Profile 的主按钮 MUST 显示“打开”，运行中 Profile MUST 常态显示“刷新”按钮。
- **FR-016**: “刷新” MUST 只重新加载所属 Profile 当前已分类的可信顶层角色，MUST NOT 接受 renderer 提交 URL，且 MUST 保留当前 Profile Session；没有运行中窗口时 MUST 拒绝刷新。
- **FR-017**: 自动恢复 MUST 是有界的；连续失败后 MUST 停止自动刷新。用户仍可通过管理卡片的“刷新”逐次手动恢复，且不得以清理 Session 或强制删除应用数据作为恢复前提。
- **FR-018**: 对页面跳转、新窗口或重定向的处理 MUST 保持登录、选服和游戏主链路在启动器内部，且 MUST NOT 回退到 Oasis 或其他国际服入口。认证子窗 MUST 使用父 Profile 的同一 partition，设置 `plugins:false`、`nodeIntegration:false`、`contextIsolation:true`、`webSecurity:true`、`allowRunningInsecureContent:false`、`enableRemoteModule:false`、`webviewTag:false`，且 MUST NOT 加载游戏窗口业务 preload；认证子窗自身的 navigate、redirect、`new-window` 和二次 popup MUST 继续执行精确 URL 分类，未知目标 MUST 阻止并保持可恢复状态。页面探针计数 MUST 以单次窗口 `LaunchFlow` 生命周期为作用域，每个 stage 最多 3 次、整个窗口流程最多 12 次，用户重新启动窗口后重置。非核心帮助、协议、客服外链及其他未知顶层目标 MUST 默认阻止，本 Feature MUST NOT 为其实现 `shell.openExternal` allowlist。全局 `no-sandbox` 是 PPAPI 运行基线的既有限制，本 Feature 只通过上述子窗隔离、精确导航和最小数据面补偿，不修改全局 sandbox 策略。
- **FR-019**: 非敏感诊断信息 MUST 足以区分发生故障的 Profile 和登录、选服、跳转或游戏加载阶段，同时不得暴露认证秘密。
- **FR-020**: 一个 Profile MUST 稳定映射到一个持久 Partition，并且同时最多拥有一个游戏窗口；不同 Profile MUST NOT 共享 Session、窗口状态或恢复计数；本 Feature MUST NOT 实现自动点击、自动选服，也 MUST NOT 注册游戏自动化 IPC、handler、command queue 或其他游戏操作入口。

### Authorized Diagnostic Access

- **Authorization**: 用户已在 2026-07-26 的当前 Codex 会话中明确授权，为定位 T056
  认证 UI 状态误判读取官方页面源码、表单、Cookie 或必要身份参数。
- **Scope and duration**: 仅限当前本地 Electron 进程、T056 使用的指定测试 Profile，以及
  完成该故障定位所需的最短时间；优先检查 DOM/frame/lifecycle，只有确有必要才扩大到
  Cookie/Storage 或身份参数。
- **Prohibited uses**: 不读取 QQ 密码字段，不修改腾讯页面认证状态，不伪造、解密、复制、
  延长、重放票据，不跨 Profile 读取，不把原始值用于登录恢复。
- **Retention and cleanup**: 原始页面或认证值不写入仓库、日志、截图、IPC 或诊断包；
  文档只保留 selector、字段名称、结构事实和脱敏结论；定位完成立即停止并丢弃临时数据。

### Key Entities

- **Profile**: 用户在启动器中的独立使用身份；拥有自己的腾讯登录状态、页面状态和游戏启动生命周期，与其他 Profile 完全隔离。
- **腾讯官方会话**: 腾讯官方认证后认可的登录状态；只属于一个 Profile，可处于有效或失效状态，不包含可由启动器采集的 QQ 密码。
- **区服选择**: 用户在腾讯官方页面上选定的有效国服区服；用于发起对应游戏页面的进入操作。
- **游戏运行实例**: 某个 Profile 进入所选区服后在启动器内部呈现的游戏内容；具有加载、可交互、失败和恢复状态。
- **流程状态**: 用户当前所处的登录、选服、跳转或游戏加载阶段，以及可见的成功、失败和恢复信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用相互独立的全新 Profile 连续执行 3 次“显示腾讯官方二维码、完成官方登录、选择有效区服并进入游戏”验收，记录 `passed/attempted`；规定矩阵 MUST 为 `3/3`。
- **SC-002**: 对有效区服连续执行 3 次进入操作，记录“在启动器内部到达对应 `game.huoying.qq.com/main.html`”的 `passed/attempted`；规定矩阵 MUST 为 `3/3`，且进入外部浏览器次数 MUST 为 0。
- **SC-003**: SC-001/SC-002 的正式连续 `3/3` 启动矩阵中，每个实例 MUST 同时记录 `game_internal`、`content_visible`、`mouse_response`；三项全部为 PASS 时该实例才计入 `passed`，规定矩阵 MUST 为 `3/3`。
- **SC-004**: Electron 主进程保持运行时，对同一 Profile 关闭并重开游戏窗口后的有效 Session 复用连续执行 2 次，并对失效 Session 返回扫码流程连续执行 2 次；分别记录 `passed/attempted`，规定矩阵 MUST 为有效 `2/2`、失效 `2/2`，且两组均不得要求删除 Profile 或 Session 数据。完整退出 Electron 主进程并重新启动应用不计入本矩阵。
- **SC-005**: 使用至少两个 Profile 执行登录、关闭并重开游戏窗口、会话失效和恢复测试时，跨 Profile 登录状态污染事件为 0。
- **SC-006**: 对“未认证状态登录 UI 加载失败”“已认证状态选服页加载失败”“进入游戏跳转失败”“游戏加载失败”四类故障分别执行至少 1 次受控验收；每类均记录“刷新”是否可见、是否只重载当前安全角色、Session 是否保留和 `passed/attempted`，规定矩阵 MUST 全部通过；无限刷新、任意 URL 加载、清理 Session 和强制手动删除应用数据的次数均为 0。
- **SC-007**: 对本功能全部用户可见入口进行检查时，Oasis 登录、国际服地区、国际服服务器和账号密码界面的可见项数量为 0。
- **SC-008**: 对扫码、会话复用、会话失效和四类失败场景产生的日志与诊断信息进行检查时，QQ 密码、完整 Cookie、可复用票据和敏感身份参数的泄露项数量为 0。

## Assumptions

- 用户拥有可正常使用的腾讯账号、扫码设备，并自行完成腾讯官方要求的确认、验证码、设备验证或风控步骤。
- 腾讯官方登录、选服和游戏服务可访问；官方服务维护、排队、封禁、风控和区服可用性不由启动器控制。
- “有效会话”以腾讯官方页面当前接受该登录状态为准；启动器不自行延长、伪造或恢复已被官方判定失效的认证状态。
- 复用有效会话表示 Electron 主进程保持运行时，用户关闭并重开同一 Profile 的游戏窗口后无需重新扫码即可继续官方选服流程；不表示完整退出 Electron 主进程后免扫码，也不表示自动恢复上次区服、自动选服或自动进入游戏。
- Electron 11.5.0 不恢复官方未设置过期时间的 session Cookie；本 Feature 接受完整进程退出
  后可能重新扫码，且不得通过复制、延长、重放或自建持久化来改变该官方会话语义。授权诊断
  可以只读检查相关值，但不得利用它们恢复登录。
- “有效区服”以腾讯官方选服页面当时允许用户进入的区服为准。
- 本功能沿用当前产品已经支持的桌面运行环境；新增运行平台不属于本功能范围。
- 官方页面文案、二维码样式和区服展示方式可能变化，验收关注用户能否完成官方流程，而不依赖固定视觉样式。
